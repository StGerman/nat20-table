Check the checkout against the commit a live run is meant for, before the run starts. Run `full-2026-11-13T15-26-00-161Z` (8.83 USD) was played on ab59b57 with local changes, 44 commits behind the intended exit build 162de4c, and did not count (`verdict.json`: FAIL, not eligible, "the checkout had changes"). Today `checkout()` in `game/src/play/preflight.ts` only prints branch, head and "with local changes" as a note that never fails, and `game/src/play/verdict.ts` marks a run not eligible for local changes (or for playing only part of the adventure), and only after the run; a clean checkout on the wrong commit passes both. First step: say where the intended commit comes from (a flag on the run command, the exit build's record, or `origin/main`).
