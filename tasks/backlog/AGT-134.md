Every agent process runs under Stas's subscription login (decision 0036), and with that login Claude Code fetches the account's claude.ai connectors (Gmail, Calendar and the rest) after its first call and adds their tools mid-session. In `full-2026-11-18T20-29-10-067Z` (build 1d79d30) the second call of 44 fresh sessions (player card votes, DM picks, the narration judge) wrote 49k to 62k tokens to the cache for answers of 2 to 30 tokens: $6.86 of the run's $13.99 API-equivalent. It shows in every full run since 2026-11-01, more or less often, because the connector fetch races the first call. The seats could never call those tools (`allowedTools`, `dontAsk`), but every seat carried their definitions in its context. The connector path is off when the process runs on an API key, which is why a cloud probe against a fake API showed nothing. Fix: `agentEnv` sets `ENABLE_CLAUDEAI_MCP_SERVERS=false` and `sessionOptions` sets `strictMcpConfig: true`. Evidence and the wider study: the Claude Doc "Decision models for the table: exploration and proposed design" (thread "Cut run cost with decision models", 2026-11-19). Check: test, no model (`sdk-session.test.ts`); then one traced `play:card` or full run on Stas's Mac, where no fresh session's second call writes more than 20k tokens.
