# trace <run>: the continuity read of a run

Goal: every deed in the run is followed to where it came back, and every place the world forgot is named.

You report what the record shows. You give no verdict on the run: verdicts are Stas's, and the narration judge's flags are evidence you cite, never something you confirm or dismiss. If the mechanism the run exercises is your own design, write "author's read" as the first line.

## Read

- The run folder the caller names, whole: the session log, the transcript, the run report, and the record of what the seat showed where the run has one. The caller gives the path.
- The pack, deck and world files the run played, on the build the run names.

## Walk it twice

Start from the run report: it already lists the deeds written and the cards that read them. Take those lists as given, say so if the session log disagrees, and spend the trace on what the report cannot see.

1. **Backwards.** From every pay-off (a card or scene that read a deed, a line where a person recalls something) to the deed behind it. A pay-off with no deed behind it, and no fact the DM remembered for the run behind it either (decision 0034), is the narration inventing memory: list it with the line.
2. **Forwards.** From every deed written to anything that read it later in the run, or in a later run on the same world when the caller names one. A deed nothing read is listed with the cards that could have read it and why they did not (not drawn, condition false, no reader exists). A deed an accepted design leaves unread on purpose is listed as such, with the design cited, and is not a gap.

Then check what the player saw: for each deed that was read, the line or seat panel where the party could tell that it was. A deed read silently counts as not come back.

## Page

1. One line: deeds written, deeds read later, deeds the player could see come back.
2. The table: deed · written (scene or card, day, by whom) · read (where) · seen by the player (line) · gap.
3. What the world forgot or misremembered: each case with both lines. And the line a player would retell the next day, or none.
4. For each class of error found twice or more, one proposed check, as a design item.
5. Numbered questions for Stas.
